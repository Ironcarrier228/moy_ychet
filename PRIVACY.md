# Исходники и история Git

Этот репозиторий был публичным и содержал архив исходников 0.9.2.
Удаление архива в новой ветке/коммите **не делает опубликованные ранее исходники приватными**.
До слияния изменения архив также остаётся в текущем дереве `main`.
После слияния он всё равно доступен в старых коммитах, тегах, ссылках PR и возможных копиях.

## Что сделано в этой ветке

- Архив исходников удалён из текущего дерева.
- Отслеживаемые публичные файлы: документация, `.gitignore`, подписанный APK, метаданные релиза и workflow публикации. Локальные Git hooks отклоняют добавление исходников приложения и ключей.
- Разработка ведётся локально, вне отслеживаемых Git файлов.
- Ключ подписи нельзя коммитить; скрипт сборки не создаёт замену отсутствующему ключу.
- Обновлятор обращается к двум конкретным файлам релиза: `update.json` и `moi-uchet.apk`.
  Ссылки GitHub `zipball_url` / `tarball_url` не используются.

## Что ещё требуется от владельца

1. Удаление архива из текущей основной ветки уже применено через PR №1. История этим не очищена.
2. Если нужно прекратить публичный доступ немедленно — временно закрыть репозиторий в настройках GitHub.
   Проверка публичных обновлений в закрытом репозитории без отдельного сервера работать не будет;
   в APK намеренно нет GitHub-токена.
3. Перед возвращением публичного доступа очистить **все** ссылки на старую историю либо создать
   чистый публичный репозиторий только для релизов, а старый закрыть/удалить после резервного копирования.
   Это отдельная административная операция. В текущей ветке она не выполнялась.
4. При необходимости обратиться в GitHub Support по поводу кешированных ссылок и ссылок PR.
   Скачанные третьими лицами копии отозвать невозможно.

GitHub автоматически показывает ссылки «Source code» для тегов.
Они архивируют дерево репозитория на момент тега. Если тег указывает на очищенное дерево,
в таких архивах будут только публичные документы, workflow и готовые бинарные файлы (если они есть в теге), а не исходники приложения.
Это не очищает старую историю.

## Ограничение APK

APK — не защита от анализа кода. Java/Dex можно декомпилировать, а встроенные HTML/JavaScript-ресурсы
можно извлечь. Отсутствие публичного архива исходников не означает невозможность изучения приложения.
Секреты GitHub и закрытый ключ подписи в APK не включаются.
